The designated Business Admin identity is `admin@salemax.qa`; the platform Super Admin remains separate. The release adds private category/role provisioning, manager/team-leader/agent organisation history and audited moves, scoped leads/calls/deals, configurable product-and-role commissions, targets and performance, and Sales Finance. Commission calculations use integer minor currency units and keep currencies separate. No production account, commission policy, sale, or customer record was created or changed.

Focused local role, scope, provisioning, commission, navigation, target and existing-screen checks pass (including the current grouped permissions/sidebar contracts). The isolated SaleMaX Sales workflow integration applies all 84 source migrations on MariaDB 11.4.13 and verifies scoped deals/calls, immutable manager and Team Leader attribution after reassignment, commission approval/payout separation, idempotent invoice and receipt creation, partial receipt allocation/reversal, audit events, and HTTP role denials. A repeat-receipt conflict caused by MySQL `DATETIME` wall-time decoding in a non-UTC client timezone was fixed by comparing stored wall-clock fields to the normalized UTC instant; the integration now passes. The full JavaScript suite reports 651/670. The current clean-upstream baseline reports 620/640 with 20 failures; the Sales branch has 19 failures and 651 passing tests, including the updated Reports asset contract.

Monthly targets and performance are now part of the existing Sales Deals workspace. The screen shows connected calls and approved sales against monthly targets, aggregates manager and team-leader performance over the current reporting tree, keeps sales amounts separated by currency, and permits owner/manager target changes with an audit event. Agents can read only their own target and performance; accountants have no target access. Focused tests cover these permissions and aggregation.

Call recording and secure playback are in source implementation and are not deployed yet. The additive schema, default-off owner policy, audible start beep, mixed-bridge capture, role-scoped playback endpoint, audit events, expiry worker and Call Center controls are implemented in this worktree. Focused recording/ARI/scope tests pass 17/17. The telephony database integration passes on local MySQL 9.6, including migration application, policy setup, capture reservation and idempotency, finish event, audit-authorized playback, and retention deletion. Production Asterisk is inactive, so real call capture cannot be verified. The business notice acknowledgement and retention controls must be set by the owner before recording can be enabled. Production MariaDB backup/apply and live schema verification remain required. The commission policy is configurable by product and role, but initial rates, eligible products, approval rules, and payout timing remain to be configured. Authenticated role-by-role browser acceptance and staff account provisioning remain open.
