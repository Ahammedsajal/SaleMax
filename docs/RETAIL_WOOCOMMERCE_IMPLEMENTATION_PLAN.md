### Explicit Woo stock-management modes — source-only follow-up, 18 November 2026

Woo variation `manage_stock` may report `true`, `false`, or `parent`. A boolean coercion treated the non-empty string `parent` as independent variation stock, which could overstate quantities and invite an incorrect mapping. Migration `20270211_retail_woocommerce_stock_management_modes.sql` adds an explicit `unknown | managed | unmanaged | parent` value to imported products and variations. Only `managed` rows with a numeric quantity can enter read-only stock comparison. A `parent` variation carries no independent quantity; legacy snapshots default to `unknown` and need a fresh sync before stock scope can be reviewed. Identity-only catalog mapping remains available.

The implementation is covered by the focused Retail/Woo suite (37/37) and Retail release-helper tests (6/6), plus JavaScript syntax and diff checks. ### Source-only increment — bounded Woo GET retry, 18 November 2026

Woo GET requests now retry a bounded set of transient transport failures and HTTP 408/425/429/5xx responses up to two additional attempts. The retry delay uses a valid `Retry-After` value up to three seconds, otherwise bounded exponential delay; larger server-requested waits stop the automatic retry and leave the sync cursor resumable for a later owner retry. Authentication, validation, redirect, and other non-transient failures are not retried. The synthetic sync test covers a dropped connection and a rate-limit response before a successful page read. This changes no Woo write behavior and is source-only.

The active-connection path also cannot accept replacement credentials through the add-store form: it returns `STORE_CONNECTION_EXISTS`. The supported owner flow is revoke the old Woo key, disconnect the store in 7Network, then reconnect the same URL with the replacement key. Disconnect retains imported snapshots; reconnect reuses the revoked tenant-scoped connection ID and resets the cursor so a fresh full scan can reconcile them. A synthetic route test checks this behavior, confirms one read-only credential check, and confirms the credentials are not returned or copied into imported records.
