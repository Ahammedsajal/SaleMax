## Mobile direct dialing and country formats

Staff dial in the mobile SIP app without CRM credentials or lead browsing. The generated mobile context accepts `+E.164` and `00` international input. On tenants with `country_code='QA'`, it also accepts an eight-digit Qatar national number and normalizes it to `+974` before the call is reserved and sent to the GSM gateway. Other national dialing plans remain disabled until their country-specific rules are added. Lead linking and do-not-call enforcement compare exact local and E.164 representations for Qatar tenants; they never match by number suffix, and duplicate lead matches remain unlinked. Qatar's regulator numbering plan lists national numbers in eight-digit format and the ITU identifies the country code as +974. ## Integration boundaries

- **Platform setup:** encrypted server-side Asterisk control credentials, endpoint reachability, version/compatibility, health, and provisioning/reload status. The Super Admin connection test reads Asterisk's module list and reports the call-control, gateway dynamic-provisioning, and browser-WebRTC module groups separately; this does not claim firewall, media, transport, or real-call readiness. Never return secrets after save; redact credentials from logs, audit, errors, exports, and UI.
- **Gateway provisioning:** represent each GSM port/channel separately, with enabled state, inbound destination, outbound eligibility, and health. Four slots are a physical channel ceiling, not four concurrent calls per tenant or a promise that the gateway supports a particular control API.
- **Tenant setup:** tenant-owned queues and extension memberships, role permissions, business hours, inbound destinations, and outbound policy. Enforce tenant and member scope on every API operation.
- **Call Center:** authenticated mobile SIP and browser WebRTC endpoints, click-to-call, inbound queue ringing/first-answer-wins, call status, and tenant/member-scoped end-call controls. Owners/managers can end tenant calls; agents can end calls they started, answered or have an active ringing leg in. Source enforces one active outbound call per member and a maximum of five originated calls per member in a rolling 60-second window, returning HTTP 429 with `Retry-After: 60`; these limits protect the finite GSM channel pool from parallel or rapid re-origination. Agent availability controls, decline/disposition/activity linked to existing leads, network-level SIP/WSS rate limiting and intrusion blocking, live signaling/media, and real-device call behavior remain open.
- **Events:** run one coordinated, reconnecting server-side ARI WebSocket consumer for the shared PBX; accept the TLS certificate, send ARI authorization in the WebSocket handshake (never in a logged query string), and do not let multiple 7Network replicas compete for or duplicate the same PBX event stream. The source worker uses a database singleton lock and bounded reconnect backoff, handles duplicate call/channel events idempotently, and on reconnect compares a bounded ARI live-channel snapshot to active 7Network legs. It reconciles calls older than 30 seconds to avoid racing new originate requests and releases orphaned channel leases. This recovery path has synthetic database coverage but still needs validation against the deployed Asterisk version and real disconnect/reconnect behavior. Recordings remain disabled until retention, access, consent, storage, and legal policy are explicitly configured.
- **Network:** the gateway topology is not confirmed; decide between direct internet and VPN/SBC only after checking the delivered gateway, carrier restrictions, and source addresses. Keep AMI/ARI private or restricted to 7Network server addresses. The gateway and mobile SIP agents share one PJSIP TLS transport, so the signaling listener cannot be gateway-IP-only while remote mobile apps connect directly; choose a VPN/SBC path for mobile SIP or public TLS SIP with strong per-device credentials, source-aware rate limiting and intrusion blocking. Apply an RTP source policy that supports every approved media peer, or use a media relay/SBC; gateway-only RTP filtering will break direct mobile media. Define and verify firewall rules before enabling the trunk. Browser calling requires a separately verified WSS, ICE/STUN/TURN, codec, and WebRTC media path; it is not implied by click-to-call. [Asterisk PJSIP transport relationship rules](https://docs.asterisk.org/Configuration/Channel-Drivers/SIP/Configuring-res_pjsip/PJSIP-Configuration-Sections-and-Relationships/) and [transport selection](https://docs.asterisk.org/Configuration/Channel-Drivers/SIP/Configuring-res_pjsip/PJSIP-Transport-Selection/) describe the transport constraints.
