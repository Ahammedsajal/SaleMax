# 7Network brand and migration record

This file is the cross-machine source of truth for the SaleMaX-to-7Network platform rebrand. Read it before changing branding, category identity, product copy, or a production release. The production release ledger remains `DEPLOYMENT.md`.

## Brand rules

- Canonical product spelling: **7Network**. Use `7Network Sales` for the private internal Sales category.
- The approved horizontal logo is `client/public/branding/7network/logo-horizontal-master-transparent.png`. It uses the supplied globe artwork with its red 7 and seven colored connection points beside the plain, fully readable word “Network.” “Net” is navy on light surfaces and pale blue on dark surfaces; “work” uses a warm sunrise red-to-orange treatment. Do not insert another globe into the word or redraw the supplied icon.
- The approved icon is the supplied globe with its red 7 and seven connection points, without a wordmark. `icon-source.png` preserves the supplied artwork; `globe-no7-source.png` is retained as a source asset but is not used in the wordmark. Responsive, favicon, PWA, and Apple touch assets are generated by `scripts/export-7network-brand.cjs`.
- `logo-light.png` and `logo-dark.png` use transparent backgrounds and the same globe-and-7 icon. The light wordmark uses navy `#0B2748` for “Net” and warm sunrise colors for “work”; the dark variant raises the text contrast while preserving the warm treatment.
- Use deep navy `#081630`, blue `#1768D4`, and cyan `#12C9F4` for the platform UI. Keep the approved red 7 and seven original point colors in the globe artwork; use semantic colors for status indicators.

## Compatibility boundaries

- `7network_sales` is the canonical category key. Existing code accepts `salemax_sales` as a compatibility alias. The production migration renames tenant/profile/settings references, but preserves published plan-version keys, plan IDs, assignments, and their history. Do not rewrite or delete those historical plan contracts; make new versions with the canonical key.
- The first-party Sales tenant already uses `7network_sales`; the human-facing category name is `7Network Sales`. Migrations `20261222_7network_sales_bot_brand.sql` and `20261223_7network_sales_domainpack_key.sql` update the saved recruitment profile name and English/Arabic greetings, then normalize its stored domain-pack key. Keep the old key available only as a compatibility path for legacy settings and published plan contracts.
- Use `https://7network.live` for public website links, chatbot company replies, and first-party recruitment links. Keep `crm.salemax.qa` as a compatibility hostname alongside `www.7network.live`; keep `SALEMAX_*` environment settings, legacy static URLs, schema migration ledger, and the existing `/careers/<tenant>` route as operational compatibility identifiers. Do not put those identifiers in new customer-facing copy. The production Nginx virtual-host file is `/etc/nginx/sites-available/7network`; its server names and certificate continue to use the existing compatibility hostname.
- Canonical platform asset filenames use `7network`. The server preserves legacy HTTP aliases for `/salemax-mobile.css`, `/salemax-brand.css`, `/salemax-homepage-copy.js`, and `/media/salemax-logo.png` plus `/media/salemax-icon.png` so cached shells and saved logo paths keep working. The old `theme-salemax` theme ID also remains mapped to `theme-7network.json` for persisted theme settings.
- Persistent chatbot config keys such as `buttonSalemax` remain compatible with saved profiles while the visible bot text and replies use 7Network.
- Do not rename tenant/customer businesses, uploaded brand assets, legal company names, email addresses, or customer records as part of the platform rebrand.
- Customer-owned branding is managed in the existing owner-only Business Profile screen. Within an authenticated tenant workspace, its saved logo takes precedence in that tenant's CRM sidebar; platform admin and businesses without an uploaded logo keep the platform brand. On verified domains, the public projection contains business display names, logo/favicon, and page title/description only; CR, address, email, phone, and website remain private. The profile migrates existing CRM logos and training-center identity fields without replacing invoice-specific profile records. Customer domains continue to expose only supported CRM routes until storefront launch is separately implemented.
- New custom-domain ownership challenges use `_7network-verification` and the `7network-domain-verification=` TXT prefix. Existing SaleMaX-format challenges remain accepted until expiry. Keep `crm.salemax.qa` as the DNS routing target because it is the existing production compatibility hostname.
- The existing compiled React bundle is not manually edited. Source-maintained screens use the updated text; `client/public/7network-brand.js` adapts platform chrome and the existing shell keeps legacy image URLs compatible.

## Production workflow

Before every production update, follow [`skills/7network-production-change/SKILL.md`](../skills/7network-production-change/SKILL.md) and `docs/PRODUCTION_ACCESS.md`. After verification, append the source commit, active release, migration status, protected rollback reference, evidence, and open gates to `DEPLOYMENT.md`, then commit and push that record so Windows and other checkouts can see the live state.

## Windows and other checkout handoff

`DEPLOYMENT.md` is the current production ledger; it records each deployed source commit and any live-only state. Before editing on another machine, fetch `origin/main`, read the latest deployment entry and this brand guide, then fast-forward the intended source branch after preserving any local edits. Pushing source does not deploy it. Keep production environment files, database exports, customer data, sessions, and backups outside Git. `crm.salemax.qa` and `info@salemax.qa` remain operational addresses, not the platform's display name.
